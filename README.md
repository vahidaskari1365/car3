# خودرویار — فاز اول پلتفرم یکپارچه خدمات و اطلاعات خودرو

پلتفرم فارسی (RTL) و واکنش‌گرا برای جستجوی فروشگاه‌ها و مراکز خدمات خودرو، راستی‌آزمایی اطلاعات، مراکز ضروری و شناسنامه دیجیتال خودرو، همراه با پنل مدیریت اختصاصی.

> این نسخه بر اساس درخواست کارفرما **بدون دیتابیس** پیاده‌سازی شده است؛ داده‌های پویا در `localStorage` مرورگر ذخیره می‌شوند. ساختار کد و مدل داده برای اتصال مستقیم به PostgreSQL/Drizzle آماده است (بخش «اتصال به دیتابیس» را ببینید).

## اجرا

```bash
npm install
npm run dev      # محیط توسعه
npm run build    # ساخت نسخه تولید
npm start        # اجرای نسخه تولید
```

## دسترسی‌ها

- سایت عمومی: `/`
- پنل مدیریت: `/admin` — ایمیل نمایشی `admin@khodroyar.ir` و رمز `admin` (دکمه «ورود سریع نمایشی» هم موجود است)
- لینک اختصاصی مالک فروشگاه (نمونه): `/verify/vrf-tire-barez-548`
- صف راستی‌آزمایی: `/admin/verifications`
- پیشنهاد اجرا و معماری: `/proposal`
- سلامت سرویس: `/api/health`

## امکانات فاز اول

### وب‌سایت عمومی
- صفحه اصلی با جستجوی سریع، دسته‌بندی خدمات، مراکز برگزیده، مراکز ضروری و نقشه راه
- جستجوی فروشگاه‌ها با فیلتر شهر، منطقه، دسته‌بندی، برند و وضعیت تأیید (`/stores`)
- صفحه اختصاصی هر فروشگاه: گالری، آدرس، تلفن، ساعات کاری، نقشه و مسیریابی گوگل مپ / بلد / نشان
- مراکز ضروری (جایگاه سوخت، CNG، تعویض پلاک، معاینه فنی) با نقشه و مسیریابی (`/centers`)
- ثبت فروشگاه توسط مالک (`/register`)
- داده ساختاریافته JSON-LD، `sitemap.xml` و `robots.txt` برای سئو

### پنل مدیریت
- داشبورد آماری، گزارش فعالیت و صف بررسی
- مدیریت کامل فروشگاه‌ها (ایجاد، ویرایش، حذف، تغییر وضعیت تأیید، خروجی CSV)
- ورود گروهی Excel/CSV با قالب دانلودی، اعتبارسنجی ردیف‌ها و پیش‌نمایش
- راستی‌آزمایی تلفنی، تولید و کپی لینک اختصاصی مالک، تأیید/رد تغییرات
- مدیریت اپراتورها و سطوح دسترسی (RBAC)
- دسته‌بندی‌ها، شهرها و برندها
- پشتیبان‌گیری JSON، خروجی CSV و بازگردانی داده

### شناسنامه دیجیتال خودرو
- چند خودرو برای هر کاربر، مشخصات کامل (سازنده، مدل، تیپ، سال، کیلومتر، پلاک، VIN)
- سوابق سرویس و تعمیر با تاریخ، کیلومتر، هزینه، مرکز خدمات و یادآور سرویس بعدی
- ثبت سوخت‌گیری و محاسبه خودکار مصرف (لیتر در ۱۰۰ کیلومتر)
- آرشیو تصویر فاکتور، بیمه‌نامه و کارت خودرو
- مسیرها: `/garage` و `/garage/[id]`

## ساختار پروژه

```
src/
├─ app/
│  ├─ (site)/            صفحات عمومی (خانه، فروشگاه‌ها، مراکز، گاراژ، ثبت، پیشنهاد)
│  ├─ admin/             پنل مدیریت و صفحات آن
│  └─ api/health/        سلامت سرویس
├─ components/
│  ├─ site/              هدر، فوتر، کارت فروشگاه، جستجو، نقشه، فرم راستی‌آزمایی
│  ├─ garage/            گاراژ و پرونده خودرو
│  └─ admin/             Provider داده، پوسته پنل و کامپوننت‌های UI
├─ data/
│  ├─ images.ts          ★ تمام تصاویر سایت فقط در این فایل
│  ├─ catalog.ts         دسته‌بندی‌ها، شهرها، برندها
│  ├─ stores.ts          داده اولیه فروشگاه‌ها و مراکز ضروری
│  └─ proposal.ts        محتوای پیشنهاد اجرا، معماری، زمان‌بندی و هزینه
└─ lib/                  انواع داده، فرمت فارسی، CSV، localStorage، گاراژ
```

### تصاویر
همه تصاویر در یک فایل متمرکز شده‌اند: `src/data/images.ts`. برای تغییر هر تصویر فقط همان کلید را در این فایل ویرایش کنید؛ هیچ آدرس تصویری در سایر فایل‌ها تکرار نشده است.

## معماری پیشنهادی برای نسخه عملیاتی

- **Next.js (App Router) + React + Tailwind CSS** برای رابط کاربری فارسی و RTL
- **PostgreSQL + Drizzle ORM** به‌عنوان دیتابیس مرکزی؛ تمام ماژول‌های آینده روی همان اسکیمای واحد
- جداول پایه: `users`, `stores`, `store_branches`, `categories`, `verifications`, `change_requests`, `operators`, `vehicles`, `service_records`, `fuel_logs`, `documents`, `essential_centers`
- لایه API مرکزی برای وب، پنل و اپلیکیشن‌های آینده؛ دسترسی نقش‌محور و گزارش کامل تغییرات

### اتصال به دیتابیس
اتصال `DATABASE_URL` و کلاینت Drizzle در `src/db` آماده است. برای انتقال این نسخه به دیتابیس:

1. جداول را در `src/db/schema.ts` با `drizzle-orm/pg-core` تعریف کنید.
2. `npx drizzle-kit push` را اجرا کنید.
3. توابع `src/lib/useLocalStore.ts` و `src/lib/garage.ts` را با Route Handlerهای `src/app/api/*` جایگزین کنید (منطق کامپوننت‌ها تغییری نمی‌کند).

## انتقال به مخزن گیت‌هاب

در این محیط، مخزن گیت راه‌اندازی نشده و به دلیل عمومی‌شدن توکن ارسالی، هیچ push‌ای انجام نشد. توکن ارسال‌شده را **فوراً در GitHub باطل (Revoke) کنید** و از روش امن زیر استفاده کنید:

```bash
git init
git add .
git commit -m "feat: phase 1 car services platform"
git remote add origin https://github.com/vahidaskari1365/car3.git
git branch -M main
git push -u origin main
```

هنگام push، به‌جای درج توکن در دستور، از GitHub CLI (`gh auth login`) یا Personal Access Token جدید با حداقل دسترسی `repo` استفاده کنید:

```bash
git push https://<USERNAME>:<NEW_TOKEN>@github.com/vahidaskari1365/car3.git main
```
